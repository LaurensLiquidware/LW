# ProfileUnity SplashScreen Manager — project constraints

Carried forward across sessions. `internal/`, `web/` and `cmd/build` are the
source of truth for behaviour; this file records the decisions behind them.

The tool was a single-file PowerShell + WPF script through 0.2.0 and was rewritten
in 0.3.0 as a Go service with an Angular interface in a WebView2 window. See
`CHANGELOG.md` for what changed and `SPARKS-AUDIT.md` for the compliance trail.

## Non-negotiable spec — ask before changing any of this

- **Target file:** `C:\Program Files\ProfileUnity\Client.NET\client-custom-logo-300x86.<ext>`.
  Both the filename and the folder are dictated by ProfileUnity itself (Liquidware
  KB 12914471137293), not by us. Allowed input extensions:
  `.bmp .jpg .jpeg .gif .png .tif .tiff`; normalized to `.jpg` / `.tif` on write,
  because ProfileUnity does not recognize `.jpeg` / `.tiff`.
- **`-target-dir`** exists so the tool can be pointed at a staging copy.
- **History + manifest** live in
  `C:\ProgramData\Liquidware\ProfileUnitySplashScreenLogoManager\`, deliberately
  outside `Client.NET` so they survive a ProfileUnity client reinstall. The
  PowerShell-era manifest format is still readable — see `internal/logo/entry.go`.
- **Elevation** is required to write to `Program Files`; the executable carries a
  `requireAdministrator` manifest.
- **`LwL.ProfileUnity.Client.CtxInit.exe`** in the target folder is what the
  splash preview launches.

## Architecture rules

- **The Go side owns all privileged work.** The interface never names a file to
  apply: browse and clipboard import record a pending candidate server-side, and
  the interface applies "the pending file". Do not add an endpoint that accepts a
  client-supplied path — that would turn the API into a way to copy any file into
  `Program Files`.
- **The loopback API keeps its guards:** per-run token, foreign
  `Origin`/`Referer` refused, no CORS headers, ever.
- **Everything ships inside the binary.** No CDN, no external font, no runtime
  fetch. The build fails if a runtime asset references an external host — don't
  work around that check, fix the asset.
- **Critical-CSS inlining must stay off** (`optimization.styles.inlineCritical:
  false` in `web/angular.json`). Angular's inliner defers the real stylesheet as
  `media="print"` and promotes it with an inline `onload` handler, which the API's
  CSP (`script-src 'self'`, no `unsafe-inline`) blocks — so the stylesheet never
  applies and the window renders unstyled. It also buys nothing here: the CSS is
  served from the executable over loopback. Do not "fix" this by loosening the CSP.
- **Render the UI in Chromium before believing it works.** WebView2 is Chromium, so
  `playwright` against the real Go server catches layout and CSP problems that no
  Go test can. Check the console for CSP violations, not just the screenshot.
- **Windows-specific code goes behind the `windows` build tag** in
  `internal/platform`. The `!windows` stub exists so the core and the API stay
  testable; its `PSM_BROWSE_PATH` / `PSM_CLIPBOARD_PATH` development affordances
  must never gain a Windows equivalent.
- **Version lives in exactly one place:** `AppVersion` in
  `internal/version/version.go`. The build reads it for the exe metadata, the
  SBOM and the zip name. Never hardcode it a second time.

## Compliance rules

- **`Spark_License.pdf` and `bom.cdx.json` ship side by side** at the top level of
  the repo and of every distributable, and the README and About dialog both point
  at them.
- **`bom.cdx.json` and `THIRD-PARTY-NOTICES.txt` are generated by the build.**
  Don't hand-edit them; change the dependency set or `cmd/build/sbom.go`.
- **A new Go dependency must have its license recorded** in `goLicenses` in
  `cmd/build/sbom.go` or the build fails. That guard is deliberate.
- **Any dependency change invalidates the SBOM and the CVE scan.** Rebuild, then
  re-run Grype against the regenerated SBOM, in that order.
- **Never commit the PrimeNG/PrimeUI license key** or any other credential. It is
  supplied only via `PRIMEUI_LICENSE_KEY` at build time and the generated
  `web/src/app/primeui-license.generated.ts` is git-ignored.

## Branding

From the Liquidware / Stratusphere UX style guide. The tokens in
`web/src/styles.css` are copied verbatim from its `colors_and_type.css` — re-copy
from there rather than retyping values.

- Brand blue `#0061A0` (primary-600) header bar, `#005084` / `#003F67` hover and
  active; base brand blue `#0072BC` is primary-500.
- Zinc surfaces: `#FFFFFF` `#FAFAFA` `#F4F4F5` `#E4E4E7` `#D4D4D8` `#71717A`
  `#27272A`.
- Good `#16A34A` / Fair `#CA8A04` / Poor `#DC2626` for status.
- 48px header bar, 14px type root, `--radius-sm` for buttons and fields,
  `--radius-lg` for cards, the guide's `--card-shadow`.
- **Button labels are weight 400, not bold** — the guide says so explicitly, and
  Aura ships 500, so the preset overrides it.
- Inter is now used for real (self-hosted variable woff2). The Segoe UI fallback
  that the PowerShell version was limited to is no longer needed.
- Copy: Title Case labels and buttons, terse impersonal system messages, no emoji.

## Tried and abandoned — don't re-attempt without a good reason

- **In-app embedded browser for image search** (WinForms `WebBrowser`, IE11/Trident).
  No WebP decoder and incomplete CSS/JS, so image search sites rendered as broken
  icons and garbled layouts. User-agent spoofing did not help; Bing was no better.
  Opening the user's real default browser is the reliable approach. This is
  moot now that the UI is Chromium-based, but the *search* flow deliberately still
  hands off to the user's own browser rather than navigating in-window — don't
  turn the app window into a web browser.
- **PrimeNG 18+ being treated as open source.** It is not. See README.md.

## Testing

- `go test ./...` covers the store, the manifest, the imaging checks and the HTTP
  API against a live server. Run it after touching any of them.
- The UI itself, the clipboard, the native file dialog and the splash preview
  need a real Windows run — they cannot be exercised on Linux.
